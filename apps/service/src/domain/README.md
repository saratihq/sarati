# The constitution — domain invariants and where they are enforced

Every rule below is LOAD-BEARING. Each has exactly ONE definition site and at
least one NAMED test that fails loudly if the rule is violated. **Changing a
rule is a deliberate amendment that says so** — never a drive-by edit. If you are
about to re-declare one of these constants or re-answer one of these questions
locally in another file: stop, import the definition instead.

| 12  | **Error-output routing** (ADR 0020): a node's error successors ride `port_type "error"` edges; the compiler lowers them into that node's `onErrorBranch` (the main flow is unchanged when no error edge is present), and the interpreter runs the error lane **iff the node throws** — in place of its main successors, **never both lanes**. | 13  | **Node & edge identity is NATIVE** (ADR 0025): a node `id` is a caller-assigned STABLE identifier (client canvas / composer `add_node`, format `NODE_ID_RE`) — identity, INDEPENDENT of the display `name`. So a rename keeps the id and diffs as a first-class `rename_node` op on that id (never an add+remove churn), and field conflicts key on that stable id (#5). The add+remove re-pairing **rename-detection heuristic is presentational-only and OFF by default** — it never feeds `applyDiff`/merge (merge runs `computeDiff` with detection OFF; a collapsed rename could corrupt it). Edge identity for diff/merge is the endpoint TUPLE `(source_node_id, source_port, target_node_id, target_port, port_type)` (`edgeKey`), NOT the edge's `id` label — enforced in `computeDiff`, `applyDiff` (`REMOVE_EDGE` by tuple), AND merge `keyOf` (ADR 0033; `edgeId` deliberately omits `port_type`, so a main+error pair SHARE an id — id-keying would collapse them, tuple-keying never does). So a `main` and an `error` edge between the same nodes never collapse (reinforces #12) and a branch/case/loop-port edge is distinguished by `source_port` | `ir/diff.ts` (`edgeKey`, `applyDiff`, `detectRenamePairs`; name-change → `rename_node`), `ir/merge.ts` (`keyOf`), `compose/apply-ops.ts` (`NODE_ID_RE`, `edgeId`)                          | `ir/native-diff-merge.spec.ts` "node identity & rename" + "the rename-detection heuristic … is presentational and OFF by default" + "merge uses rename-detection OFF" + "edge identity" + "edge identity is the TUPLE" (same-id error edge survives a main removal; main+error same-nodes both land) |
| 14  | **Agent tool binding is edge-native** (ADR 0045): a tool is a `port_type: 'tool'` edge from an `orchestr:agent` node to the bound tool node (any action, or a first-class `orchestr:call_workflow` sub-workflow). | 15  | **A protected branch only takes change through an approved review**: merge is checked in `mergeBranchIn` — the ONE merge implementation (#5) — so the branches page inherits it rather than each caller re-deciding; and `commit` refuses outright, because a gate only on merge is walk-around-able by editing the branch directly. `rollback` deliberately still lands: it restores an existing version and is the documented recovery path. The reviews path keeps its own stricter precondition (THAT review must be approved) plus the fresh-red-test rule. An approval may not come from the review's own author **where another member exists** — otherwise the gate is self-satisfiable; a workspace with nobody else to ask is exempt so it cannot deadlock                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | `workflows/branch.service.ts` `mergeBranchIn`                                                                                                                                              | `invariants.e2e-spec.ts` "a protected target refuses any merge no approved review authorised, through BOTH entry points"; `review-self-approval.e2e-spec.ts` (all three: blocked with a teammate, allowed solo, rejection unaffected)                                                                                                                                                                            |

Rules of the vault:

- `src/ir/` imports nothing outside `src/ir` + `src/common` (dependency-cruiser: `moat-ir-is-pure`).
- `src/compiler/` imports only compiler/ir/runtime/common (`moat-compiler-bounded`).
- Every NEW invariant lands here with its definition site and its named test, in the same change.
- The trigger predicate `isTriggerNode` has ONE definition site (`compiler/compile-ir.ts`); the reconciler + compiler import it, never re-declare it. Guarded by `domain/single-definition-sites.spec.ts`, which exists because `compose/apply-ops.ts` was once found carrying a divergent private copy that missed the `…_trigger` suffix — so the composer refused to retype a node the rest of the system treats as the trigger. **Documented-but-unguarded is how that drift happens: every one-definition-site rule needs a test, not just a row.**

The whole table is enforced by `test/invariants.e2e-spec.ts`, `domain/single-definition-sites.spec.ts` and the `moat-*` rules in `.dependency-cruiser.cjs` — all of which run under `pnpm check`.
